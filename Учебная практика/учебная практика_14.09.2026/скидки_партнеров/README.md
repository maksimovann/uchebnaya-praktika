# CRM: список партнеров и скидок

Проект использует схему предыдущей практики: `partners`, `products`, `shipments`. Исходные файлы `data/import_partners.csv` и `data/import_sales.txt` взяты из предыдущего этапа. Один исходный заказ с `partner_id = 4` отклоняется, поскольку такого партнера нет.

## Запуск без PostgreSQL

Из папки задания:

```powershell
python server.py
```

Откройте `http://127.0.0.1:8000`. При первом запуске создается локальная SQLite-копия данных `practice.sqlite3`. При последующих запусках она сохраняется. Для отдельной копии можно указать `--db другой_файл.sqlite3`.

## Подключение к PostgreSQL прошлой практики

Если база PostgreSQL уже создана по `schema.sql` и заполнена через `import_data.sql`, установите драйвер:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-postgres.txt
```

Учебная база на этом компьютере называется `partners_db` и находится на PostgreSQL 18 (`localhost:5432`). Запустите из папки задания:

```powershell
.\.venv\Scripts\python.exe server.py --postgres --pg-database partners_db --pg-port 5432 --port 8766
```

Если папки `.venv` нет, сначала создайте окружение командой `python -m venv .venv`, затем установите драйвер командой выше. Программа спросит пароль пользователя `postgres` в терминале. Символы пароля при вводе не отображаются, пароль в файлы проекта не записывается. После сообщения `Подключено к PostgreSQL` откройте `http://127.0.0.1:8766/`. Не закрывайте терминал, пока пользуетесь приложением.

Можно также задать строку подключения в переменной окружения `PARTNER_CRM_DATABASE_URL` и запустить `python server.py`. В обоих вариантах подключение проверяется до запуска сервера, а API читает PostgreSQL напрямую при каждом запросе; локальная SQLite-копия не используется.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

`discount.py` содержит отдельную функцию расчета. `database.py` и `postgres_database.py` выполняют `LEFT JOIN`, `SUM(quantity)` и `GROUP BY` для получения общего количества товара. В SQLite представление `sales_history` отображает данные таблицы `shipments`; в PostgreSQL такое же имя используется в SQL-запросе как CTE. `COALESCE` гарантирует `0` при отсутствии истории, после чего функция возвращает скидку `0%`.

В прежней схеме нет типа партнера и имени директора как отдельных полей. Интерфейс выводит фактически доступные название, ИНН, телефон, почту и рейтинг. Логотип и иконка в `resources` созданы для этого проекта, поскольку исходные фирменные файлы не были приложены к заданию.
